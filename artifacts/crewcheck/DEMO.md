# CrewCheck demonstration script

This walkthrough uses fictional data. It demonstrates the interface only; it is not a medical procedure.

1. Open the Crew dashboard and point out the fictional crew profiles, prototype notice, local storage status, and persistent Emergency control.
2. Open **Emergency**, choose a fictional crew member, and acknowledge the first onboard-help prompt. Show the timestamped event history.
3. Select **Condition changed**. Point out that the app records the change without deleting prior events and directs the helper to the applicable trained-crew protocol.
4. Record equipment as unavailable and show that the prototype does not substitute another device or procedure. Add a helper using the helper-flow control.
5. Open **Handoff**. Review the generated text and download the structured JSON. The handoff contains recorded facts and labels unknown details rather than filling them in.
6. Open **Observe**, save a fictional observation, then use **Review saved entries** to inspect missing and uncertain fields.
7. Open **Measure** and show the BP and pulse-ox manual entry forms. Point out the source-review and mission-applicability limitations; do not present entered values as clinical interpretation.
8. Open **Habitat**. Explain that the fictional timeline shows possible overlap only; it does not establish exposure or cause.
9. Open **Mission**, switch among the fictional profiles, inspect sample equipment locations, set a communication delay only if the scenario has one, and view routines and source links.
10. If running a production HTTPS build, wait for the offline-preparation status before attempting a disconnected demo. The disconnected walkthrough has not yet been verified.

Do not claim that data is transmitted, that NASA endorses the app, or that any procedure was clinically reviewed.
